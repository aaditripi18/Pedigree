Pedigree: do models come from where they say they do?

A model card's base_model tells licence checks, procurement reviews and the Hub what a model is built on. Nobody checks it. Pedigree checks it from the weights, on a frozen random sample of the Hub, with a verifier measured on ground truth first.

29%of Hub models whose weights show a public parent do not declare it (105 of 364; 95% interval 24–34%)
1.3%of declared bases are contradicted by the weights (3 of 227; 95% interval 0.4–3.8%)
600models audited, drawn at random from three download tiers of the Hub's top 100,000; every one is accounted for

Weights cannot be compared for 94 declared pairs. The behaviour instrument, pre-registered for them, applied to 0: 66 pairs with a model above 2B parameters; 28 pairs with neither a shared language-model output nor a shared label set. On ground truth it did not separate distilled students from independent ones (H9, H12, H14, H14b), so it is reported as its own category, never moves H3, and is not run on larger models.

164 comparisons in the audit ended in a file-reader error. After the readers were fixed they were scored again (E2r): all but 99 now score (those use GGUF tensor types outside llama.cpp's published list), and no verdict changes: H2 106/375 undeclared; H3 3/257 contradicted; H7 (a) 20/24; (b) 77/230.

Check a model yourself

The browser checker runs the same comparison in this page, reading only file headers and small slices of tensors from the Hub. The CLI does the same for PyTorch, GGUF and MLX files too:

pip install git+https://github.com/aaditripi18/Pedigree
pedigree verify hf:org/model --base hf:org/base
